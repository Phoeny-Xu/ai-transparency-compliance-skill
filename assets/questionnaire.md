# 信息采集问卷模板

> 使用方式：A组在对话框用选项逐轮提问（可一轮问完）；按A组答案条件触发B组对应题目。**B组改为勾选清单呈现**：有明确选项的题目标注（单选）/（多选），每题固定加「其它（请补充）___」与「不确定（按最严口径）」；仅数值估算（如月活数量）与开放描述（如生成内容模态细节）保留手动填写。用户答「不确定」按最严口径处理。
>
> **触发条件锚定规则（防漂移）**：B组题及所有报告生成规则的触发条件**只能引用A6（查询范围）**，不得引用A4（适用性事实采集）。A4对三法域逐一采集事实，不设勾选跳过，因此「A4含X」恒为真、不能作为触发条件。新增题目或修改触发条件时，一律锚定A6。

## A组：简单问题（对话框选项）

| 编号 | 问题 | 选项 | 触发的B组题 |
|------|------|------|-------------|
| A1 | 你的产品是否自研/自训生成式AI模型？ | 是 / 否（纯接入第三方模型）/ 部分（微调第三方模型） | 任意选项→B2 |
| A2 | 服务对象类型？ | 向公众提供（B2C）/ 向特定企业或机构客户提供（B2B/B2G）/ 仅内部使用 / 混合模式（兼有） | 除「仅内部使用」外→B1、B4 |
| A3 | 产品功能构成（**按用户初始描述分两种问法，不重复采集已知信息**，见下方备注） | 见备注 | 含生成且模态含音频或视频→B5 |
| A4 | 适用性事实采集（**对三法域逐一采集，不设勾选跳过**）。每个法域固定采三项：(a)用户量级档位（0/趋零、<1万、1-10万、10-100万、100万-1000万、1000万+、不确定）；(b)在该法域是主动营销、运营、提供服务（含设当地语言界面、面向当地推广、开放注册、境内支付，**「开放注册」为典型情形举例之一、非穷尽；企业通过逐一签约主动向当地客户销售、运营、提供服务，亦属主动提供**），还是仅被动可达（用户自行获取或访问）？(c)关键触达因素（多选）：境内实体、境内推广、语言界面、境内商店上架、境内支付、无 / 不确定 | 中国大陆 / 欧盟 / 加州，各附(a)(b)(c) | 量级与触达事实写入画像；触发B组题见A6 |
| A5 | 产品生成的文本/图像/音频/视频，是否可能以拟真写实方式生成或呈现使公众误认为真实存在的人物、事件或场景的内容（既包括再现真实对象，也包括虚构但足以令人误信为真实的角色、事件、场景），而非明显虚构的卡通、抽象、艺术化风格？ | （单选）是 / 否 / 不确定 | 是→B5a |
| A6 | 本次查询范围（多选）：中国大陆 / 欧盟 / 加州。选满三个=三地全量；选一个=单法域；选两个=两地组合。**A6仅控制报告义务详述展开范围；未选法域的A4适用性事实仍须采集并写入画像，用于报告「法域适用性说明」与「未覆盖维度」节，不展开义务详述** | 按所选法域触发对应B组题 | 任意 |
| A7 | 产品是否专门为/主要面向就业招聘、教育录取、信贷评估、执法司法、医疗诊断等对自然人权益有重大影响的场景设计？（即产品定位即此类应用，如下游为招聘系统、教育录取系统、信贷风控系统、执法司法辅助、医疗诊断辅助） | （单选）①专为/主要用于上述场景（产品定位即此类应用） ②通用工具型产品（非专为此类场景设计，如通用大模型、通用办公助手；义务取决于下游如何使用） ③不涉及（功能上不可能用于此类场景） | ①→报告头部加欧盟Annex III高风险预警（仅预警，不展开）；②③→见下方A7备注 |

> A2判定备注：向**不特定**企业开放注册使用的SaaS，按「向公众提供」处理；仅与特定客户逐一签约提供的，按B2B处理（中国「向境内公众提供」要件的认定见role-mapping.md法域适用性节）。**本备注的「开放注册即公众」为skill采用的保守推定口径**，法律文本本身未直接界定「企业客户」是否构成「公众」；报告应当在「假设与不确定项」节标注此推定为保守口径，监管实务中存在按B2B处理的讨论空间。
>
> **A2开发者/API服务适配说明（防误选）**：面向**开发者**提供模型API/SDK、模型权重下载等服务的，因不特定开发者可开放注册使用，按「向公众提供」处理（与B2C同路径，进入B8预设触发后做三项事实检验）；**仅**向签约企业客户逐一提供API/模型的，按B2B处理。用户可能因「卖给企业/开发者」误选B2B——而误选B2B可能经B8 B2B例外反向翻转备案结论，故凡开放注册的开发者服务一律按向公众提供判定，不得按B2B。

> **A4备注（向公众提供认定，与A2协同）**：向不特定企业开放注册使用的SaaS，视为「向公众提供」；仅与特定客户逐一签约提供的，视为非公众（B2B）。该认定用于A2服务对象类型判断，避免B2B SaaS误判为非公众而漏采B组题（边界细则见role-mapping.md法域适用性节）。

> **A7备注（通用工具型/不涉及）**：①之外才进入本备注。②通用工具型产品：不触发报告头部高风险预警；报告加「下游部署提示」——若下游客户将本产品部署于就业、教育、信贷、执法、医疗等场景，客户自身可能落入欧盟AI Act Chapter III高风险义务，应当另行专项评估。建议措施节可以提示：在客户协议中明确用途限制，以**降低风险敞口**（注意：用途限制条款不等于免责安排，其法律效果取决于管辖法域与具体场景，不得写成「约定用途限制即可免责」）。③不涉及：不触发任何高风险预警与下游提示。

> **A5备注（预设=是，防自评失真）**：面向公众的生成式服务，因生成内容不可预料且文本类内容难以一眼辨识AI属性，预设A5=是（与B8预设同构），按触发处理并标注该预设；仅当产品生成内容明确为明显虚构的卡通、抽象、艺术化风格、无任何写实呈现（既非对真实对象的写实再现、亦非虚构但足以令人误信为真实的内容）时，按否处理并标注推理依据。本预设仅用于确保B5被采集，不代表对具体标识义务的认定。

> **A3两种问法（先判断用户初始描述，再选用）**：
> - **情形一：用户已表明产品含生成/合成内容功能**（如自述"我的产品是生成式AI""能生成图片/文本"等）→ 不再问是否生成，改问：「除生成功能外，产品是否还包含检测内容是否由AI生成的功能（如AI内容检测工具）？」选项：含检测功能 / 不含 / 不确定。另采集**贵司产品对终端用户实际输出/展示**的生成内容模态（多选）：文本 / 图像 / 音频 / 视频 / 虚拟场景 / 3D / 数字人/虚拟人（含真人形象克隆）。
> - **情形二：用户未表明**→ 问：「产品包含以下哪些功能（多选）：A. 生成或合成内容（即贵司产品向终端用户实际生成/展示的内容，由AI产出文本、图像、音频、视频、3D、数字人/虚拟人等）；B. 检测内容是否由AI生成（如提供AI内容检测工具）；C. 仅对内容进行分析、评分、推荐（不生成也不检测）」。选A的，另采集**贵司产品对终端用户实际输出/展示**的生成内容模态（多选）：文本 / 图像 / 音频 / 视频 / 虚拟场景 / 3D / 数字人/虚拟人（含真人形象克隆）。
>
> A3判定备注：(1)检测功能影响欧盟Art. 50(2)检测可及性义务与加州covered provider免费AI检测工具义务的落地方式，采集后写入画像。(2)仅选C（纯分析型）的产品原则上不触发以「生成合成内容」为前提的标识义务（中国标识制度、欧盟Art. 50(2)、加州实质义务均以生成/合成内容为前提），但欧盟Art. 50(1)交互告知、Art. 50(3)情感识别告知可能仍适用，报告中应当说明。

> **B9询问备注（须先朗读定义并举实例）**：向用户询问B9时，不要只问一句"是否具有情感识别或生物特征分类功能"，须先说明定义并举例：
> - "情感识别系统"指根据自然人的生物数据（如面部表情、语音、步态、生理信号）识别或推断其情感或意图的AI系统；例如：通过摄像头判断用户"开心/愤怒/紧张"的情绪识别功能、通过语音判断客户"是否满意"的客服质检功能。
> - "生物特征分类系统"指根据自然人的生物数据将其归入特定类别（如年龄、性别、族裔、健康状态、性取向、政治观点）的AI系统；例如：通过人脸照片自动归类年龄组或性别组。但"附属于另一商业服务且因客观技术原因严格必要者除外"——例如视频会议软件为压缩带宽而做的粗略年龄段分组，若该分组仅为技术适配、不构成独立功能，可排除。
> 询问顺序建议：先问"产品是否采集人脸、语音、行为等生物数据并据此判断情绪或归类人群？"，再核对上述定义。

> B4判定备注：不采集「用户是否会在站外二次传播」——内容一旦可导出，站外传播非产品方所能控制，不是有效的判定事实。环节④（传播平台）的判定只看**产品自身**是否提供传播功能。

> **B3a判定备注（加州月活B2B口径，解释性判断）**：§22757.1(d)门槛为"over 1,000,000 monthly visitors or users"。**B2B SaaS场景下，「月活用户」的合理口径为与平台订立账户的企业客户数，下游终端消费者非平台用户、不计入**。此为解释性判断，法条未明确定义"用户"；仅当企业客户数超100万且加州公开可访问时才构成covered provider。边界情形（企业账号数接近门槛）建议取得加州当地法律意见。
>
> **B3a/B3b题间矛盾即时校验规则（防回填确认才发现）**：B3a（全球月活）与B3b（全球独立月用户）同为全球口径。若B3b档位显著低于B3a（如B3b<100万而B3a>1000万，或B3b<200万而B3a>1000万），或B3a<100万而B3b≥200万，agent**必须立即回问澄清**两者统计口径是否一致（如是否含重复用户、是否同一统计周期），不得延后到回填确认环节。澄清后仍矛盾的，按矛盾处理规则（产品实际描述>勾选）处理并写入报告假设节。

> **B1判定备注（环节⑤主体归属，易错）**：深度合成规定第13条与标识办法第7条的义务主体是**应用程序分发平台的运营者**（应用商店等），不是上架的App开发者。因此：B1④=是才触发环节⑤；B1②选了「第三方应用商店上架」的开发者**不构成**环节⑤主体——相反，上架时商店会向其要求说明是否提供AIGC服务并核验标识相关材料（标识办法第7条），这对开发者是上架审核的**实务配合事项**，写入报告「建议措施」节（预先准备备案编号、标识技术说明等材料），**不得**写成开发者的法定义务。
>
> **B1④询问备注（带示例清单）**：向用户询问B1④时，必须带示例，且须强调"自身运营"与"上架他人商店"的区别。示例：苹果 App Store、华为应用市场、小米应用商店、OPPO应用商店、vivo应用商店、应用宝、Google Play、Samsung Galaxy Store、Amazon Appstore 等。关键区分："我的App在苹果App Store上架"→选"否"（属于B1②第三方应用商店上架）；"我运营一个类似App Store的应用商店，他人App在我这里上架"→选"是"。
>
> **B1②判定备注（境内/境外应用商店的中国法域影响）**：B1②「第三方应用商店上架」本身不触发环节⑤，但影响中国大陆「向境内公众提供」的适用性判定：境内应用商店（华为应用市场、小米商店、App Store 中国区等）上架通常视为**主动提供**；境外应用商店（Chrome Web Store、Google Play、App Store 海外区等）上架、且无境内推广/中文界面/境内支付/境内实体的，按**被动可达**处理，须标注假设（境外商店在大陆被屏蔽者更倾向被动可达）。该区分直接决定中国法域义务是否展开。

> **B1③判定备注（GenAI hosting platform，§22757.1(g)+§22757.3.2）**：构成要件=网站/应用+供加州居民下载GenAI系统源码或模型权重+有偿无偿均计入；**含自有模型权重的自持下载站，不限第三方托管**。义务内容为派生义务：2027-01-01起不得**明知**而提供未按§22757.3设置披露的GenAI系统下载。用户自身同时是covered provider的，主义务在§22757.3；hosting platform这层主要在托管第三方模型时产生独立意义。术语瑕疵提示：定义条款（§22757.1(g)）用「GenAI hosting platform」，义务条款（§22757.3.2）用「GenAI system hosting platform」，同一法内措辞不统一，引用时以定义条款为准。
>
> **B2判定备注（欧盟下游可依赖上游标记规则，与追问联动）**：欧盟provider不得以「接入第三方模型」为由当然豁免Art. 50(2)机器可读标记义务。报告应按B2(a)(b)追问答案分路径处理：①上游已提供符合Art. 50(2)的标记方案且合同约定下游可依赖 → 下游可在产品中保留并呈现上游标记，但仍须证明该方案满足要求（委员会指南§4.2.1第(74)段）；②上游未提供标记或无合同约定 → 下游provider须自行实施标记方案，不得空依赖。该规则不影响「以自己名义投放市场」即构成provider的定性。
>
> **B2「以自己名义」定性规则（agent 行为约束）**：B2第二问只采集事实（品牌/界面/合同归属），**不得**把"您是否属于欧盟 provider"这类法律判断题抛给用户。agent 应依据用户回答的事实，结合role-mapping.eu-rules判定规则，自行推断欧盟 provider/deployer 定性，并在「回填确认」环节向用户说明推断结论及依据。用户只需回答"产品以谁的名义、谁的界面、谁的合同对外呈现"，不须理解 provider/deployer 概念。
>
> **B2判定备注（加州covered provider「creates, codes, or otherwise produces」边界，个案判断框架）**：加州法条未明确定义「授权接入+应用层定制」是否构成「produces a GenAI system」。Skill采用以下判定要素框架，结论须标注为「个案判断」：
> - **强指向构成covered provider**：自研/自训基础模型；对第三方模型进行持续预训练、后训练、SFT、RLHF等实质性模型训练；以自有品牌向市场提供独立GenAI系统。
> - **强指向不构成covered provider**：纯API调用第三方模型，仅做Prompt工程或轻量封装；未改变模型权重/架构；服务核心依赖第三方模型能力。
> - **中间地带（须个案判断并标注）**：在第三方模型之上训练场景适配器/LoRA、构建垂直领域评分模型、或进行大量RAG/工作流编排但未触及基础模型权重。报告应当列明倾向性结论并提示「无执法指引/判例，建议取得加州当地法律意见」。
> 该框架不影响欧盟provider判定——只要「以自己名义投放市场」即构成欧盟provider。

> **B5a判定备注（中国侧 A3 模态与高仿真能力核对，防止漏勾）**：A3 采集的是产品**输出模态**（文本/音频/视频/图像/虚拟场景/代码等），B5a 采集的是是否具备**深度合成规定第17条第1款所列的高仿真能力**。二者相关但不等同，必须逐项核对。当 A3 含某模态但 B5a 未勾选对应高仿真能力时，agent **不得直接采信「以上皆无」**，须按以下映射追问澄清：
> - A3 含**文本** → 追问是否模拟自然人进行智能对话/智能写作（如客服机器人、AI写作助手、营销文案）；仅生成代码/结构化数据/固定模板字段的，可接受不勾选，但须在报告假设节写明「文本输出不模拟自然人」。
> - A3 含**音频/语音** → 追问是否为合成人声/仿声（如语音克隆、AI配音）；仅生成音乐/音效/非语音音频的，可接受不勾选。
> - A3 含**视频/图像** → 追问是否含人脸生成/替换/操控、姿态操控；仅生成风景/产品/抽象图像或无人脸视频（如数据可视化、动画渲染）的，可接受不勾选。
> - A3 含**虚拟场景或 3D** → 追问是否为沉浸式拟真场景（可供参与者体验或互动的虚拟场景）；仅生成非交互式3D模型、静态虚拟背景的，可接受不勾选。
> - A3 含**数字人或虚拟人（含真人形象克隆）** → 通常对应人脸生成/替换/操控或沉浸式拟真场景，须追问交互形态；非交互式数字人视频按人脸操控/生成处理，交互式数字人按沉浸式拟真场景处理（见cn-rules.md模态映射表）。
> 用户无法明确区分或拒绝澄清的，将 B5a 改选为「不确定（按最严口径）」，并写入报告假设节。
>
> **B5a×技术支持者义务联动（防漏判）**：若角色判定最终含「深度合成服务技术支持者」（环节②），则 B5a 勾选的合成人声/仿声、人脸生成/替换/操控等能力，除用于第17条第1款显式标识判定外，**同时**触发该技术支持者的第14条（提供人脸人声等生物识别信息编辑功能的，提示使用者取得单独同意）与第15条第2款（提供人脸人声生成/编辑的模型、模板等工具的，**现时触发**安全评估）。agent 应在报告中国节「深度合成服务技术支持者」小节单独列示，不得因主体另构成服务提供者而省略或并入。
>
> **B5b判定备注（欧盟Art. 50(1)交互告知事实采集）**：B5b 仅采集交互形态事实，不直接判定法律义务。Art. 50(1)对「与自然人交互的AI系统」设交互告知义务，并不以音视频仿真为前提——纯文本智能对话/写作/客服类系统同样落入。B5b=「无（纯API或后台系统，无自然人交互界面）」时，Art. 50(1)不触发；B5b含任一交互形态时，写入画像「欧盟Art. 50(1)交互告知义务待核」，由agent结合role-mapping判定。
>
> **A3×B5b联动说明（防"答非所问"误判）**：A3 已勾选文生图、图生视频、AI音乐、数字人/虚拟人等模态的，通常可直接认定存在「输入提示词获取生成内容」的交互（B5b），agent 应据此预填 B5b 并回显用户确认；用户明确否认存在自然人交互的除外。回填确认阶段不得指责用户"答非所问"，而应表述为"根据您描述的生成模态，拟认定产品存在自然人交互；如您认为实际不存在，请修正"。
>
> **B10判定备注（能力≠已实施；A3 vs B10 即时矛盾校验）**：B10 采集的是**已实施的透明度措施现状**，A3 采集的是**产品是否含检测功能的能力**。二者口径不同，但存在关联：若 A3 答「不含检测功能」，而 B10 勾选「AI检测工具」，则出现事实矛盾。agent **必须在问卷阶段立即弹窗回问**，不得延后到回填确认环节由 agent 自行推断。回问模板：
> > 发现前后回答不一致：您此前表示产品「不含检测功能」，但又勾选了「已具备AI检测工具」。请确认：
> > - (a) 产品实际含检测功能，A3 应修正为「含检测功能」；
> > - (b) B10 指的是使用外部第三方检测工具，非产品自身功能；
> > - (c) 其它（请补充）___。
> 用户确认后更新画像；回填确认阶段须将该矛盾点及最终采用结论列入「假设与不确定项」节。

> **B6触发说明（企业自身对外发布）**：B6触发收紧为「企业自身对外发布AI生成内容」这一活动，非终端用户使用产品发布内容（终端用户发布时，是那些用户自身构成deployer、自行担Art. 50(4)义务，与被评估企业无关，最多在建议措施节提示合同传导安排）。活动本质对应价值链环节④中平台自产内容、环节⑦内容发布者、环节③应用服务方在自家产品内自行发布AI生成内容（如AI新闻摘要推送）。纯对外提供模型/服务、内容发布全由下游做的，跳过B6。自研模型的provider若同时用自有模型生成内容对外发布，一身两角：模型侧担provider义务（Art. 50(1)/(2)），发布侧担deployer义务（Art. 50(4)），报告按角色分小节呈现（角色叠加规则见role-mapping.md）。
>
> **B6防误触发提示**：B6仅因「企业自身对外发布**以向公众通报公共利益事项为目的**的AI生成文本」而触发（典型如新闻、公共信息）。**「运营内容平台」或「允许用户发布内容」本身不等于B6触发**——后者是B3b/B4②的事实，触发的是加州large online platform义务或中国传播平台核验义务，而非欧盟Art. 50(4)公共利益文本披露。Agent在判定B6时应当区分：B6问的是「贵司自己是否发布新闻/公共信息类AI文本」，B3b/B4②问的是「贵司是否运营供用户发布内容的平台」。

> **B8判定规则（重要，防止用户自评失真）**：不采信用户对「舆论属性或社会动员能力」概念的直接自答（可能误答或避答）。面向公众提供的生成式服务，B8**预设触发（即默认按触发处理）**备案+安全评估口径；但此预设**须经B8-1/B8-2/B8-3 三项客观事实检验**——仅当三项客观事实均明显为否（无任何公众表达/传播渠道、不涉及公共议题、规模极小）时，才按不触发处理并同样标注推理依据。预设是默认状态，例外出口是事实检验，二者为两段式结构，不互为概率。依据：2018年《具有舆论属性或社会动员能力的互联网信息服务安全评估规定》第2条以渠道类型列举（论坛、博客、微博客、聊天室、通讯群组、公众账号、短视频、网络直播、信息分享、小程序等或附设相应功能；提供公众舆论表达渠道或具有发动社会公众从事特定活动能力的其他服务），不以经营者自我定性为准。
>
> **B8 B2B场景例外（防过度触发）**：当A2=「向特定企业或机构客户提供（B2B/B2G）」或A2=「混合模式」但以B2B交付为主、且B8-1「无任何公众表达/传播渠道」与B8-2「不涉及公共议题」均明显为否时，B8-3 的规模量级**不构成独立触发因素**，按不触发安全评估+算法备案处理，但须在报告「假设与不确定项」节标注「因缺乏公众表达渠道且内容不涉及公共议题，虽终端消费者规模大，仍按不触发处理」。此例外仅适用于纯B2B交付且不向不特定企业开放注册的场景；若A2备注已将「不特定企业开放注册」按向公众提供处理，则不适用本例外。
>
> **★B8前置闸门（向境内公众提供，先于三项事实检验）**：备案+安全评估以「向境内公众提供/具有境内舆论属性」为根本前提。**先做闸门判断，再做三项事实检验**——若产品/服务不面向境内公众提供（典型情形：生成环节在境内、内容仅向境外发布，App不向境内公众开放，如出海内容工具的境内生产管线），则**备案+安全评估整体不触发**，无需再检验B8-1/B8-2/B8-3 三项事实；此时仅深度合成规定标识义务（第16/17条，以「境内应用技术」为连接点）可能适用。闸门判断与三项事实检验是两个层级，不得在闸门已排除的情况下仍按三项事实触发备案（防止「境内生成/境外发布」场景被机械判定触发）。详见role-mapping.md法域适用性节「境内生成/境外发布分层框架」。

> **矛盾处理规则（前后回答不一致时）**：当用户勾选/作答与产品实际功能描述不一致（如A3勾选音视频模态但产品实为纯文本工具），按以下优先级判定：(a)用户明确更正 > (b)产品实际功能描述（最初自然语言描述）> (c)勾选的选项/模态（用户可能误解题意，优先级最低）。**闭环**：当(b)产品实际功能描述与(c)勾选选项不一致时，优先以产品描述为准，但必须在「判定前的回填确认」环节显式标注差异并请用户确认，不得跳过确认直接采纳；最终采用结论须写入报告「假设与不确定项」节（按三列模板：矛盾点 / 拟采用结论 / 后续动作）。

> **B8「面向公众」定义与A2分支（填B8-3量级用）**：「面向公众」指不特定多数人可访问，排除仅企业内部员工/签约客户员工使用的封闭场景。B8-3 量级按A2分支：A2=向公众提供（B2C）/混合→直接问产品用户量级；A2=B2B/B2G→先问前置事实「产品生成内容是否会被公众接触到（如客户把生成内容用于对公众展示/传播）」：是→估算触达公众的量级（非企业客户数）；否→按「不触达公众」记录。本分支与role-mapping「与问卷A2的关系（防语义重叠）」节闭环。
>
> **B8-3 量级前置事实的双用途（防漏判技术支持者）**：上述 A2=B2B 的「生成内容是否会被公众接触」前置事实，**同时**用于「深度合成服务技术支持者」身份判定（与备案量级判断并列，非替代）：下游将生成内容用于对公众展示/传播（面向公众出产品）→ 上游构成技术支持者（深度合成规定第23条）；下游仅内部使用、生成内容不触达公众 → 链条整体不适用，上游既不构成服务提供者也不构成技术支持者。该结论应写入报告中国节角色结论，不得仅用于备案量级。

> **B8-3 量级备注（规模极小非法定量化）**：「规模极小」无统一法定量化标准——2018年《具有舆论属性或社会动员能力的互联网信息服务安全评估规定》第2条仅列举渠道类型（论坛、博客、公众账号、短视频等），不规定用户数，属个案法律判断。常规参考：数万级用户/调用方一般视为极小，百万级须谨慎；量级填不清或选「不确定（按最严口径）」时，按最严口径推定触发（与B8预设触发同构）。

## 判定前的回填确认（强制）

完成问卷后，必须先把用户画像摘要回显给用户确认，用户明确确认后方可进入阶段2效力核验与报告生成。**回显格式须严格区分「事实采集结果」与「agent 推导的法律结论」两列**：用户只需确认事实列（产品形态、服务对象、输出模态、交互方式、月活量级、传播渠道等），法律结论列（拟判定的三地角色、各法域适用性、B8 触发结论、EU Art. 50 触发结论等）由 agent 说明其推导依据，用户仅确认或更正事实，不直接回答法律判断题。agent 推断出的主体画像须经用户背书，方得作为后续判定与报告的基础。若用户更正画像，须按前「矛盾处理规则」节标注差异并采用更正后结论，写入报告「假设与不确定项」节。

> **回填确认禁止行为（★强制）**：
> - 不得在回填阶段自行推翻问卷阶段已即时校验的矛盾（如 A3 与 B10 检测能力矛盾、B3a/B3b 量级矛盾、A3 与 B5a 模态-高仿真能力矛盾），这些矛盾必须在问卷阶段即时弹窗澄清并更新画像；回填阶段仅做记录与最终确认。
> - 不得把法律判断 disguised 为用户事实问题（如「您是否认为贵司构成 covered provider？」），用户只回答事实，法律结论由 agent 推导。

> **中国法标识办法主体确认（★强制，仅A6含中国大陆时）**：除上述通用画像外，须就《人工智能生成合成内容标识办法》第2条适用前提向用户单独确认，回显格式如下：
> - 主体要件：拟判定贵司属于符合《互联网信息服务深度合成管理规定》或《生成式人工智能服务管理暂行办法》规定情形的**网络信息服务提供者**（此为标识办法第2条的上位概念/umbrella，具体落于下述角色类型之一或若干）；
> - 行为要件：拟判定贵司**开展人工智能生成合成内容标识活动**（服务提供者自行标识、应用分发平台/网络信息内容传播服务提供者履行核验义务，均属标识活动具体形态）；
> - **说明**：《互联网信息服务算法推荐管理规定》与AI透明度/标识义务无直接连接点，仅在生成合成内容通过推荐系统分发时作为适用背景按需提及，不作为本 skill 前置性判断依据；
> - 拟判定具体类型（umbrella「网络信息服务提供者」之下的具体角色）：**{深度合成服务提供者 / 深度合成服务技术支持者 / 生成式人工智能服务提供者 / 应用分发平台 / 网络信息内容传播服务提供者 / 第10条内容发布者 / 不适用}**。
> - **环节②触发提示**：若用户画像含价值链环节②（模型/算法技术支持方，API/SDK/模型权重，不直接面向终端用户），除标识办法第2条主体（深度合成服务提供者/生成式AI服务提供者等）外，应另行确认是否构成「深度合成服务技术支持者」（《互联网信息服务深度合成管理规定》第23条）。该角色**不是**标识办法第2条项下的标识义务主体（标识义务仅落在服务提供者），而系深度合成规定下的独立角色，其自有义务为第19条第2款参照备案、第14条训练数据管理、第15条算法机制审核（均非透明度义务），应在报告中国节单独列示，不得因《暂行办法》第22条将其并入生成式AI服务提供者而遗漏。技术支持者身份成立以「下游面向公众出产品」为前提；若下游仅内部使用（A2=B2B 且 B8-3 量级前置事实为「否」），链条整体不适用，不得判为技术支持者。
